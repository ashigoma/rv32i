# 概要
- svでrv32iを書く
- テストはspikeとsvでトレースログを比較することによって行う

# ビルドと実行
```
make
make check
```

# cpu側の特殊仕様まとめ
- 疑似標準出力
    - 0x20000000 へのstoreで、sv側から標準出力に1文字書き出し (spike標準)
    - 0x20000004 へのstoreで、sv側から標準出力に16進整数を書き出し
    - 0x20000008 へのstoreで、sv側から標準出力に整数を書き出し
- 実行開始
    - 0x80000000 のentry pointから実行開始する
- 実行停止
    - sv側では、ebreak命令
    - spike側では、特定アドレスへのstore

# 開発とテストの流れを考えたもの
- メモリマップを確定
- boot.Sにsp初期化, call, return, shutdownのみを残し、数命令のプログラムをいくつか動かしてテストしながらsvを書く
- すべて通ったら、boot.Sをbss, data初期化ありのものに差し替えてcの複雑なプログラムを動かしてテスト
